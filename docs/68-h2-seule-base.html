Une seule base de données : H2

18 octobre 2026 · branche develop · point « MySQL/PostgreSQL non testés » de docs/TODO.md (§ 6, P2)

Résumé
  1. Le logiciel embarquait les pilotes de deux autres bases (MySQL et PostgreSQL), et un commentaire promettait qu'il suffisait de changer trois lignes pour les utiliser.
  2. C'était faux : les migrations de démarrage sont écrites pour H2, et la sauvegarde copie les fichiers H2. Avec une autre base, le démarrage ou la première sauvegarde aurait échoué.
  3. Ces bases ne peuvent pas être testées sur ce poste (pas de serveur, pas de réseau fiable). Les deux pilotes sont donc retirés, et le commentaire dit maintenant la vérité : H2 seulement.
  4. Le logiciel livré est plus léger, et personne ne sera tenté par une configuration qui ne marche pas.

1. Pourquoi retirer plutôt que tester

Figure 1 — Garder un pilote qui ne marche pas avec le reste n'apporte qu'une fausse piste.

La boutique tourne sur un seul ordinateur, avec sa base dans un fichier : H2 est fait pour ça. Les deux autres pilotes ne servaient à rien, et leur présence laissait croire qu'on pouvait changer de base sans rien d'autre.

2. Si une autre base devient nécessaire

  • Réécrire les migrations de bootstrap/ dans une syntaxe commune (ou passer à Flyway, voir le point « Schéma en ddl-auto=update »).
  • Donner à la sauvegarde un moteur pour cette base (aujourd'hui seul H2BackupEngine existe).
  • Remettre le pilote dans pom.xml et lancer toute la suite de tests contre un vrai serveur.
