Seuil de stock bas par produit

17 octobre 2026 · branche develop · point « Seuil de stock bas par produit » de docs/TODO.md (§ 4, P2)

Résumé
  1. Chaque produit peut avoir son propre seuil d'alerte : 50 sacs de riz, 2 cartons d'huile.
  2. Sans seuil propre, le seuil commun de 10 s'applique, comme avant : rien ne change pour les produits non réglés.
  3. Le seuil se règle dans la configuration du produit, onglet Fiche ; un champ vide rend le seuil commun.
  4. Les listes, les tableaux de bord et le filtre « Alertes uniquement » suivent tous la même règle, à un seul endroit du serveur (StockPolicy).
  5. Les écrans ouverts voient le changement tout de suite.

1. Le problème

Un produit était « en alerte » sous 10 unités, quel qu'il soit. Pour le riz vendu par dizaines de sacs par jour, l'alerte arrivait trop tard ; pour un produit vendu une fois par mois, elle restait allumée en permanence.

2. Ce qui a été fait

Figure 1 — Un seul calcul, pour tous les écrans : le seuil du produit s'il en a un, sinon le seuil commun.

Le seuil est compté dans l'unité de base du produit (celle du stock). Il est gardé dans une nouvelle colonne du produit, vide par défaut ; la base existante n'a rien à reprendre. La requête des produits en alerte (tableaux de bord) compare chaque produit à son propre seuil, ou au seuil commun.

4. À éviter / attendu

À éviter
// le seuil répété dans chaque écran
product.getStockQuantity()
    .compareTo(BigDecimal.TEN) < 0
Attendu
// une seule règle
StockPolicy.isLowStock(product)
// = stock < thresholdOf(product)
