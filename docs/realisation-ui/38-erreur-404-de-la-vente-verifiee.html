UI-88Erreur 404 de la page de vente : vérifiée, normale

17 octobre 2026 · branche develop · point UI-88 de docs/todo-ui.md

Résumé
  1. L'erreur 404 vue dans la console du navigateur sur la page de vente a été retrouvée.
  2. Elle vient de la recherche d'un code-barres inconnu : le serveur répond « aucun produit ne porte ce code ».
  3. C'est la réponse prévue : c'est elle qui ouvre la fenêtre « Code inconnu » (UI-21). Aucun message d'erreur n'est montré au caissier.
  4. Le navigateur écrit toujours une réponse 404 en rouge dans sa console ; l'utilisateur ne la voit pas.
  5. Aucun code modifié. Au chargement normal de la page, aucune requête n'échoue.
Sommaire
  • 1. La vérification
  • 2. Pourquoi ne rien changer
  • 3. Tableau récapitulatif

1. La vérification

Le navigateur de test a enregistré toutes les réponses en erreur de la page Nouvelle vente (compte de Fatima), d'abord au chargement, puis après la lecture d'un code que personne ne porte.

Figure 1 — Le 404 est la réponse « aucun produit » ; l'écran la transforme en fenêtre « Code inconnu ».
MomentRéponses en erreur
Chargement de la pageaucune
Lecture d'un code inconnu404 /api/products/lookup?code=9990009998887 — une seule

2. Pourquoi ne rien changer

« 404 » est la façon normale pour un serveur de dire « je n'ai pas cela ». L'interface le sait déjà : l'appel est marqué « 404 attendu » (productByCode, dans ui/…/core/api/catalog.api.ts), donc aucun message rouge n'apparaît à l'écran. Répondre autrement demanderait de changer le contrat du serveur, que l'application mobile utilise aussi, sans rien gagner pour le caissier.
