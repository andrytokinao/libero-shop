UI-20Onglet Codes-barres : scanner pour associer

17 octobre 2026 · branche develop · point UI-20 de docs/todo-ui.md

Résumé
  1. L'onglet « Codes-barres » de la configuration montre une ligne par unité (pièce, paquet, carton…) avec son code.
  2. Avec une douchette : on clique dans la ligne, on scanne, le code est enregistré tout seul. Sur téléphone, un bouton 📷 lit le code.
  3. Un code déjà porté par un autre produit est signalé tout de suite, avec son nom ; il n'est pas envoyé.
  4. Le code existant d'une ligne est sélectionné quand on y entre : le code scanné le remplace au lieu de s'y ajouter.
  5. Chaque ligne s'enregistre seule : changer le code du carton ne touche à rien d'autre.

1. Le problème

Le code de l'unité de base se tapait dans la fiche ; celui d'un carton, dans le formulaire « Modifier » de l'unité. Un code déjà utilisé n'était découvert qu'à l'enregistrement, par un message d'erreur.

2. Ce qui a été fait

Figure 1 — Une ligne par unité ; le code déjà pris est arrêté avant l'envoi.

L'enregistrement réutilise ce qui avait été fait pour le code inconnu à la caisse (UI-21) : seul le code change, ni le prix, ni le prix d'achat, ni le contenu du carton. Le serveur refuse de toute façon un code déjà pris ; la vérification à l'écran évite seulement d'aller jusque-là.

3. Le résultat en images

Nadia — responsable de dépôt « Lait en poudre 400g », vendu à l'unité et au carton.

Figure 2 — Une ligne pour l'unité de base, une pour le carton.
Figure 3 — Ce code est celui du « Riz 5kg » : c'est dit, et « Enregistrer » reste grisé.

4. À éviter / attendu

À éviter
Le curseur arrive à la fin du code existant ; la douchette ajoute le sien : « 99900011122236009009000099 ».
Attendu
Le code existant est sélectionné quand on entre dans la ligne ; la douchette le remplace : « 6009009000099 ».
