UI-83« Annuler » dans le message

17 octobre 2026 · branche develop · point UI-83 de docs/todo-ui.md

Résumé
  1. Après une réception ou une correction de stock, le message du bas garde un bouton « Annuler » pendant 7 secondes.
  2. « Annuler » écrit le mouvement inverse, comme le « ⋮ » d'une réception passée : rien n'est effacé, l'historique montre les deux.
  3. Un bon de livraison de plusieurs produits s'annule en une fois, tout ou rien (nouveau côté serveur).
  4. Si une partie de la marchandise est déjà vendue, l'annulation est refusée avec le message habituel.
  5. Partout où l'on reçoit ou corrige : page Approvisionnement, Corrections, fenêtre « Réception », « Ajouter du stock » et « Corriger le stock » du menu produit.

1. Le problème

Une faute de frappe (« 200 » au lieu de « 20 ») se remarque juste après avoir validé. Pour la rattraper, il fallait retrouver la ligne dans la liste des réceptions et passer par son « ⋮ ». Le message qui confirme l'opération est pourtant déjà sous les yeux.

2. Ce qui a été fait

Figure 1 — « Annuler » n'efface rien : il ajoute le mouvement inverse et marque la réception.

Un seul service, StockUndo, ajoute le bouton au message et appelle la bonne annulation : une réception, un bon entier ou une correction. Les listes de réceptions et de corrections se rechargent d'elles-mêmes après l'annulation ; le stock affiché partout suit par les mises à jour en direct.

Côté serveur, POST /api/stock/deliveries/cancel annule toutes les réceptions d'un bon dans une seule transaction : si une ligne est refusée, aucune n'est annulée.
