Modèles d'unités et fenêtre de configuration sans défilement de côté

16 octobre 2026 · branche develop · demande directe (hors docs/todo-ui.md)

Résumé
  1. La fenêtre Configuration d'un produit est plus large sur ordinateur. Sur téléphone, elle prend tout l'écran et chaque unité devient une carte. Elle ne défile plus jamais de côté.
  2. Nouveau : les modèles d'unités. Un modèle est une liste d'unités à réutiliser, sans prix. Le modèle « Poids » (g, kg, tonne) est créé tout seul.
  3. À la création d'un produit, comme dans sa configuration, on coche les unités d'un modèle. Le prix de chacune est proposé et reste modifiable.
  4. Pour un riz compté en kapoka, on dit une seule fois « 1 kg = 3,5 kapoka ». Le kg et la tonne sont ensuite calculés.
  5. En ajoutant une unité à la main, on peut cocher « Ajouter aussi au modèle » : dans un modèle existant, ou dans un nouveau modèle à nommer, puis à renommer si besoin.
  6. Un modèle ne change aucun produit : ses unités sont copiées. Renommer ou supprimer un modèle ne touche pas aux produits déjà faits.

1. Le problème

  • Défilement de côté. Le tableau des unités a sept colonnes. Dans une fenêtre de 680 pixels, il débordait : il fallait faire défiler de gauche à droite pour voir le bénéfice ou les boutons. Sur téléphone, c'était pire.
  • Unités retapées à chaque produit. Le gramme, le kilo et la tonne se retapaient pour chaque produit vendu au poids, avec leur contenance. C'est long, et une faute de frappe fausse le stock à chaque vente.

2. La fenêtre de configuration

1Sur ordinateur

La fenêtre passe à 1 040 pixels de large. Les champs du produit se rangent sur autant de colonnes que la largeur permet. Le tableau des unités tient en entier : plus de barre de défilement.

2Sur téléphone

La fenêtre prend tout l'écran. Le titre et les boutons du bas restent visibles. Chaque unité devient une carte : son nom en titre, puis une ligne par chiffre (contient, prix de vente, prix d'entrée, bénéfice, code-barres).

3Moins de texte en haut

Le long paragraphe d'explication est replié dans « Comment ça marche ? ». Il s'ouvre d'un clic.
Figure 1 — Le tableau des unités : avant (il débordait), après sur ordinateur (il tient), après sur téléphone (des cartes).

3. Les modèles d'unités

Un modèle est une liste d'unités avec leurs contenances, sans prix ni stock. Exemple, le modèle « Poids » créé tout seul au démarrage :

UnitéS'écritEn grammes
gunité de référence du modèle1
kg1 000 g1 000
tonne1 000 kg1 000 000

On s'en sert à trois endroits :

ANouveau produit

« Autres unités depuis un modèle » : on coche le kg, la tonne… et on règle leurs prix. Elles sont créées avec le produit, dans la même opération.

BConfiguration d'un produit

« Ajouter des unités depuis un modèle » : même chose pour un produit qui existe déjà. Une unité que le produit a déjà est grisée (« déjà présente »).

C« Ajouter aussi au modèle »

Sous « Ajouter une unité » : l'unité tapée à la main (un « sac 25 kg » = 25 kg) part aussi dans un modèle. On choisit le modèle, ou « ＋ Nouveau modèle… » avec son nom.

« Gérer les modèles » ouvre une fenêtre pour renommer un modèle, lui ajouter ou retirer des unités, le supprimer, ou en créer un nouveau (Volume, Cartons…).

Un modèle est copié sur le produit, il n'y reste pas attaché. Si l'on modifie ou supprime le modèle, les produits déjà faits gardent leurs unités. Les ventes passées ne sont jamais touchées.

4. Comment le modèle rejoint le produit

Le modèle dit seulement comment ses unités se comparent entre elles. Pour les mettre sur un produit, il faut savoir où le modèle rejoint ce produit. Le serveur le cherche dans cet ordre :

Figure 2 — Où le modèle rejoint le produit : d'abord ce que le produit dit déjà, et seulement sinon une question.

Chaque unité ajoutée passe ensuite par les mêmes règles qu'une unité tapée à la main : au plus trois décimales, pas exactement une unité de base, prix supérieur à zéro, nom libre. Si une seule est refusée, aucune n'est ajoutée, et le message dit laquelle (« "g" : la contenance accepte au plus 3 décimales… »).

Quand le produit a déjà l'unité de référence, la nouvelle unité est écrite comme dans le modèle : la tonne reste « 1 000 kg ». Si l'on corrige plus tard le kg du riz (3,6 kapoka au lieu de 3,5), la tonne suit d'elle-même.

6. À éviter / attendu

À éviter
// Un « kg = 3,5 kapoka » mis dans un modèle partagé :
// faux pour le sucre (≈ 4 kapoka le kg).
modèle Riz : kg = 3,5 kapoka
Attendu
// Le modèle ne dit que ce qui est vrai partout,
// le produit dit le reste, une fois :
modèle Poids : kg = 1 000 g, tonne = 1 000 kg
riz : 1 kg = 3,5 kapoka  →  tonne = 3 500 kapoka
À éviter
/* une colonne de plus = un défilement de côté */
.table-scroll { overflow-x: auto; }
Attendu
/* étroit : chaque ligne devient une carte */
@media (max-width: 760px) {
  .un-table td[data-label]::before { content: attr(data-label); }
}
