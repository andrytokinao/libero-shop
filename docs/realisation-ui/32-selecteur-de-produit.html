UI-30Un seul sélecteur de produit : chercher ou scanner

16 octobre 2026 · branche develop · point UI-30 de docs/todo-ui.md

Résumé
  1. Sur Approvisionnement et Corrections de stock, la longue liste déroulante de tout le catalogue est remplacée par un champ « Produit ».
  2. On tape deux lettres du nom : les produits correspondants s'affichent avec leur stock actuel.
  3. On peut aussi scanner le code-barres (douchette, ou caméra du téléphone dans l'application).
  4. Un code imprimé sur un carton choisit le produit et le carton : la livraison se compte en cartons sans autre choix.
  5. Après un choix, le nom reste sélectionné : le code scanné ensuite le remplace, on enchaîne les produits sans cliquer.

1. Le problème

Pour enregistrer une livraison ou corriger un stock, il fallait dérouler une liste de tout le catalogue et y trouver le produit à l'œil. Avec quelques centaines d'articles (une boutique dont le catalogue a été importé), c'était long, et la douchette ne servait à rien sur ces pages.

2. Ce qui a été fait

Un composant unique, app-product-picker, remplace la liste sur les deux pages. Ce qu'on y tape est lu de deux façons, dans cet ordre :

Figure 1 — Le champ « Produit » essaie d'abord le code-barres, puis le nom.

La recherche se fait sur la liste de produits que la page a déjà (elle est tenue à jour en direct) : pas d'attente du serveur à chaque lettre. Elle ignore les accents et les majuscules (« cafe » trouve « Café »), comme la recherche de Prix et unités, qui utilise maintenant la même fonction.

4. À éviter / attendu

À éviter
<!-- tout le catalogue dans une liste -->
<select>
  @for (product of products()) {
    <option>{{ product.name }}</option>
  }
</select>
Attendu
<app-product-picker
  [products]="products()"
  [selected]="selectedProduct()"
  (picked)="pickProduct($event.product.id,
                        $event.packagingId)" />

Le champ garde le focus après un choix. Sans sélection du nom, le code scanné ensuite s'ajoutait au nom (« Lait en poudre 400g9990001112223 ») et rien n'était trouvé : c'est corrigé et testé.

Tests : tests de l'interface au vert (214). Aucun changement côté serveur. Pas de défilement de côté à 1366 px ni à 390 px.

Hors périmètre, signalé : les fenêtres « Ajouter du stock » et « Corriger » ouvertes depuis le menu « ⋮ » ont déjà leur produit ; elles n'ont pas besoin du sélecteur. La réception de plusieurs produits (UI-31) le réutilisera.
