Version 1.0.0 : le serveur dit le même numéro que son installateur

18 octobre 2026 · branche develop · point « Version 0.0.1-SNAPSHOT » de docs/TODO.md (§ 6, P3)

Résumé
  1. L'installateur Windows était déjà numéroté 1.0.0, mais le serveur qu'il installe se disait 0.0.1-SNAPSHOT.
  2. Ce numéro est celui que la mise à jour compare avec la version publiée : les deux doivent être le même.
  3. Le projet est maintenant en 1.0.0, et l'installateur prend ce numéro au lieu d'en avoir un à lui : un seul endroit à changer à la prochaine version.
  4. Les métadonnées vides du modèle de projet sont remplacées : nom « Libero Shop », description, éditeur « Kinga Digital » (le même que celui de l'installateur).

1. Ce qui a été fait

Figure 1 — Un seul numéro, lu par l'installateur, le serveur et la mise à jour.

Vérifié après construction : le fichier d'information du serveur (build-info.properties) dit build.version=1.0.0. Le nom du fichier .jar livré ne change pas : il est déjà masqué (compte rendu 16).

2. À la prochaine version

Changer <version> dans backend/pom.xml (par exemple 1.0.1), toujours en chiffres seulement : l'outil qui fabrique l'installateur refuse les suffixes comme -SNAPSHOT.
